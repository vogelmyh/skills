## 为当前执行环境绑定访问通道

1. 先确认当前请求明确包含目标环境的只读诊断或日志核验，并确认当前使用者已经通过组织流程获批。Skill 本身、历史快照和网络地址都不能授予访问权。
2. 在当前执行环境发现可用通道，例如使用者自有的 SSH 配置、BytePlus 受控会话或专用只读工具。SSH alias 可由每位使用者自行命名；不要要求与文档作者一致，也不要把 alias、SSH `User` 或身份文件路径写回 Skill。
3. 将通道绑定到一个逻辑目标，并用非秘密元数据核验云资源/节点身份、目标地址、端口、跳板关系、严格 host-key 策略和目标服务。SSH 场景可用 `ssh -G <当前使用者的-host-token>` 检查 `hostname`、`port`、`proxyjump`、`hostkeyalias`、`stricthostkeychecking` 和 `identitiesonly`，但不要输出 `user` 或 `identityfile`。
4. 只有绑定与上表及可信控制面一致时，才执行范围严格的非交互只读命令。诊断记录写逻辑目标、云资源名、节点标签和查询时间窗；本地 alias 仅在当前会话中使用，不作为可共享证据。
5. 若当前环境没有可用绑定，则改为生成供获批操作员执行的准确命令和脱敏要求。不得从其他人的配置猜测账号、复制身份文件、绕过跳板机、关闭 host-key 校验或把私网 IP 直连失败解释为目标服务故障。

## 共享和停止边界

- 可以共享：逻辑目标、云资源名、带日期的网络拓扑、服务名、非秘密日志路径、只读命令模板、验证信号和停止条件。
- 不得共享或固化：个人 SSH alias、SSH `User`、`IdentityFile`、私钥/证书、known-hosts 内容、控制台会话、临时端口转发、Token、数据库/MQ URL 或任何凭据值。
- host key 变化、目标身份不一致、路由绕过既定边界、需要新账号/凭据/权限，或完成诊断需要状态变更时立即停止。
- 历史文档中出现的 alias、工作区状态或“本机已验证”只描述原操作者当时的证据，不得作为另一位使用者的当前配置或授权依据。
